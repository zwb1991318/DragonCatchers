# Dragon Catchers（捞龙小队）游戏设计与总体规划

> 状态：v0.2 草案（首轮玩法评审后更新） · 2026-10-11
> 灵感来源：2011 年 Feelingtouch 的 iOS 游戏《Dragon Hunter》（已下架）。本项目只复刻玩法，不使用原版的任何素材。

## 1. 一句话定位

横屏卡通守城射击游戏：拉弓把来袭的龙射进河里，船自动打捞获得收益，再用收益升级弓箭、船、城墙和收集相关技能，一关一关打下去。

本文统一用“收集收益”描述打捞带来的成长资源。原草案称为金币，本轮讨论也提到食物；最终资源名称、是否需要换算，以及是否另设可分配的技能点，暂不定案。

## 2. 核心设计决定

| 项 | 决定 |
|---|---|
| 屏幕方向 | 横屏（只支持横屏） |
| 射箭操作 | 必须从弓箭手身上起拖，朝拖动的反方向射箭，拖动距离决定力度；显示抛物线预瞄虚线，拖回零距离可取消；装填期间可提前瞄准并持续拉住 |
| 船 | 自动打捞：龙掉进河后，船自己开过去捞。龙会被水流冲走，超时没捞到就没了 |
| 胜负条件 | 本关所有波次的龙全部死亡则胜利；城墙 HP 归零则失败。龙进入攻击距离后可远程攻击城墙，无需接触城墙 |
| 每关初始状态 | 每关开始时重置局内状态，城墙恢复到当前升级等级对应的满 HP；长期成长进度另行保存 |
| 收集与成长 | 前期没有相关技能或加持时，收集收益可以较低；收益主要用于技能升级，成长系统预留收益系数加成 |
| 美术风格 | 卡通，轻松明快 |
| 平台 | iPhone 优先，最低支持 iOS 17 |

## 3. 画面布局（横屏）

```
┌──────────────────────────────────────────────────────────┐
│ [城墙HP ████░░]   收益 120    波次 2/5          [⏸]      │
│                                        🐉 ←               │
│   🏹                              🐉 ←                     │
│  ███                                          🐉 ←        │
│  ███  城墙                                                │
│  ███                                                      │
│~~⛵~~~~~~~~~~~~~~~ 河（水流 →） ~~~~~~~~~~~~~~~~~~~~~~~~~~│
└──────────────────────────────────────────────────────────┘
```

- **左侧**：城墙，弓箭手站在墙头。
- **底部**：一条横贯全屏的河，水流从左往右，船停在城墙脚下的码头。
- **右侧和上方**：龙分波次从这里飞进来，飞向城墙。
- **顶部 HUD**：城墙血条、收集收益、波次进度、暂停；从 M3 开始加主动技能按钮。

## 4. 核心循环

```
射龙 → 龙掉进河 → 船捞龙 → 运回码头获得收益
  ↑                                    ↓
进入下一关（更难）  ←  用收益升级技能
```

- 射击取舍：远距离击落龙更难；等龙靠近会更容易瞄准，但龙进入攻击距离后可能已经对城墙造成伤害。具体射程、弹道和命中难度在原型中调整。
- 自动收集：已经落水的龙要赶在被冲走前捞上来，船的效率影响实际回收量。暂不把“近处击落一定赚得更多”设为既定规则。
- 长期成长：前期缺少相关技能或加持，收集收益可以较低；收益主要用于技能升级，船速、载量和收益系数等成长项逐步改善收集收益。

## 5. 系统需求

### 5.1 射击
- 拉弓起点：必须在弓箭手身上按下并开始拖动，其他空白区域不能起手。
- 方向和力度：射箭方向与拖动方向相反，拖动距离决定力度，力度有上限；持续拉住不动时保持当前瞄准和力度，不因持有时间增加力度。
- 取消：拖回起点、拖动距离归零时取消本次拉弓，不发射箭。
- 发射：装填完成后，在有效拉弓状态下松手发射。
- 抛物线预瞄虚线，长度可以作为升级项。
- 装填间隔：发射后要等一段时间才能再射；装填期间可以提前拉弓瞄准，并一直拉住，装填完成不会自动发射。装填未完成就松手的处理留待输入实现时明确。
- 箭受重力影响飞行，箭头朝向跟着速度方向转。
- 命中判定和伤害；箭飞出屏幕或落进河里后自动消失。

### 5.2 龙
- 属性：血量、飞行速度、飞行路径（直线或波浪）、攻击距离、攻击力、攻击间隔、基础回收价值。
- 行为：飞进屏幕 → 飞向城墙 → 进入攻击距离后悬停并远程喷火 → 被击落后下坠 → 落进河里。攻击城墙不要求龙接触城墙。
- 龙的 HP 归零即视为死亡；后续下坠、漂流和打捞属于收集流程，不影响死亡判定。
- 种类（M3 全部做完）：

| 种类 | 特点 |
|---|---|
| 普通龙 | 基准数值 |
| 快速小龙 | 血量少、速度快、基础回收价值低 |
| 装甲龙 | 血量多、速度慢 |
| 远程喷火龙 | 在较远处停下，用火球攻击 |
| Boss | 血量很多，会召唤小龙，有特殊攻击 |

### 5.3 河与船
- 落水的龙随水流向右漂，漂出屏幕就没了。
- 船自动选择目标：先排除来不及追上的龙，再优先捞最快会漂出屏幕的龙。
- 目标选定后保持追踪，直到捞到、目标丢失或已无法追上，再重新选择，避免频繁掉头。
- 前期载量按条数计算，普通龙每条占一个位置；特殊龙和 Boss 的载量规则后续再定。
- 船有速度和载量，满载或河里没有龙时就回码头卸货结算。
- 打捞与卸货耗时、返航途中能否顺路打捞，在收集系统实现时补充。

### 5.4 城墙
- HP 和受击反馈（闪红、震动）。
- 每关开始时恢复到当前 HP 上限，上一关的损伤不带入下一关，不需要关间付费修墙。
- 自动修墙作为局内恢复能力，仍可保留为后续升级项。

### 5.5 关卡与波次
- 每关由若干波组成，每波写明龙的种类、数量和出场间隔。
- 全部用数据文件配置，不写死在代码里。
- 胜利：本关所有波次均已生成完毕，且所有龙都已死亡；不能因为两波之间暂时没有龙就判胜。
- 失败：城墙 HP 归零。
- 胜负判定不以打捞完成为前提。胜负已确定时，河中和船上尚未结算的收益如何处理，留待结算流程实现时明确。
- 每关开始时重置局内状态：按当前升级配置初始化城墙、弓箭和船，清空上一局的龙、箭、船载货和波次状态；长期资源余额、升级等级和关卡进度不属于局内重置范围。
- 当前先搭建前期框架；单关时长、波次节奏、教学安排和难度曲线暂不细化。

### 5.6 经济与升级

收集收益主要用于技能升级。以下为成长项，不等同于 5.7 的局内主动法术；技能树结构以及是否另设可分配的技能点，后续再定。

| 类别 | 升级项 |
|---|---|
| 弓箭 | 箭伤害、装填速度、多重箭、特殊箭（毒箭持续掉血、眩晕箭让龙停住、火箭溅射伤害） |
| 船 | 船速、载量 |
| 城墙 | HP 上限、自动修墙 |
| 收集收益 | 收益系数加成；其他加持形式待定 |

前期没有相关技能或加持时，允许回收效率和收益较低。框架需支持基础回收价值及收益系数，具体系数、升级价格和成长曲线放在数据文件里，后续试玩调整。

### 5.7 主动技能（法术，有冷却时间）
- 火雨：对一片区域造成伤害。
- 冰冻：所有龙减速或停住几秒。
- 狂风：把龙往后吹退。
- 闪电：对单个目标造成高伤害，可以连锁到附近的龙。

### 5.8 存档
关卡进度、收集资源余额、各项技能升级等级。星级规则尚未定义，留待成长系统阶段补充；局内重置不清除长期存档。

### 5.9 界面
主菜单、关卡选择、游戏内 HUD、暂停、胜利和失败结算、商店。

## 6. 技术架构

### 6.1 技术选型
- **Swift + SpriteKit**：游戏场景用 SpriteKit，靠它的物理引擎做箭的抛物线和龙下坠。
- **SwiftUI**：主菜单、商店、结算这些界面用 SwiftUI，通过 `SpriteView` 嵌入游戏场景。
- **XcodeGen**：工程配置写在文本文件 `project.yml` 里，便于修改和版本管理；生成的 `.xcodeproj` 不放进 git。
- **单元测试**：用 Swift Testing 或 XCTest。

### 6.2 目录结构

```
DragonCatchers/
  project.yml
  App/            SwiftUI 入口、菜单、商店
  Game/
    Scenes/       GameScene（一关的主场景）
    Entities/     Archer, Arrow, Dragon, Boat, Wall, River
    Systems/      WaveSpawner, CollectionSystem, Economy
    Input/        拉弓手势
  Data/           levels.json, dragons.json, upgrades.json
  Model/          纯逻辑：存档、升级曲线、波次解析（不依赖 SpriteKit）
  Tests/          单元测试
  docs/           设计文档
```

### 6.3 设计原则
- **数据驱动**：数值都放在 JSON 里，调手感时不用改代码。
- **逻辑和画面分离**：经济、升级、波次、弹道计算写成纯 Swift，可以单元测试。
- **一个文件只管一件事**：每个实体和系统都独立成文件，方便逐个修改。
- **美术先用占位图形**，到 M4 再换成卡通素材（来源：Kenney.nl、itch.io，或者 AI 生成后再调整）。

## 7. 里程碑路线图

| 里程碑 | 内容 | 完成标准（你可以自己验证） |
|---|---|---|
| **M0 工程搭建** | XcodeGen 工程、git、空的横屏场景 | 模拟器里能打开一个横屏的空场景 |
| **M1 核心循环** | 一关完整流程：从弓箭手起拖的反向拉弓、取消和装填期间瞄准、预瞄线、龙分波来袭并远程喷火、龙落河漂流、船自动捞、收益结算、输赢判定和每关状态重置。用彩色方块代替美术，预留收益系数配置 | 能完整玩一关并赢或输，手感经你确认；先跑通框架，暂不要求完成节奏和难度平衡 |
| **M2 成长系统** | 商店和技能升级（伤害、装填、船速、载量、城墙 HP、收益系数）、存档、10 个关卡、关卡选择 | 收集收益能用于升级，退出后再进进度还在；每关重置局内状态，保留长期成长 |
| **M3 内容扩充** | 5 种龙、特殊箭、4 个技能、Boss，扩充到 30 关、3 个区域 | 每个区域末尾有 Boss，难度曲线经你试玩认可 |
| **M4 美术和音效** | 卡通美术、动画、音效、音乐、打击感（震屏、粒子） | 看起来像个成品 |
| **M5 上架准备** | 图标、确认商店里没有重名、真机测试、TestFlight 和 App Store 提交 | 上架或在 TestFlight 上可用 |

每个里程碑开始前，会先单独写一份详细的实现计划。

## 8. 暂不做的事

内购和广告、联网和排行榜、iPad 专门适配、多语言（先只做中文）、安卓版。这些等 M5 之后再考虑。

## 9. 版权原则

复刻的只是玩法。名字、美术、音效全部原创或者使用允许商用的素材，不用原版的素材，也不用 "Dragon Hunter" 这个名字。

## 10. 待定问题

- 资源定义：食物与金币的最终命名、是否存在换算关系，以及是否另设可分配的技能点。
- 结算细节：胜负确定时尚在河中、船上的收益如何处理；失败或主动退出时，已结算收益是否保留。
- 输入与收集细节：装填完成前松手如何处理、打捞和卸货耗时、返航途中能否顺路打捞。各系统实现时再明确。
- 后续体验设计：关卡时长、波次节奏、教学、难度曲线和星级规则，前期框架搭好后再讨论。
- 是否上架、是否收费：到 M4 结束时再决定。上架需要 Apple 开发者账号，每年 99 美元。
- 中英文名：暂定"捞龙小队 / Dragon Catchers"，上架前在 App Store 查一下有没有重名。
